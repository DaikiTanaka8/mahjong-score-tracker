# API設計

要件定義書([機能要件.md](機能要件.md))、DB 設計書([DB設計.md](DB設計.md))、画面設計書([画面設計.md](画面設計.md))に基づく API 設計(第1段階: MVP)。バックエンドは FastAPI。

## 1. 共通事項

| 項目 | 内容 |
|------|------|
| ベース URL(開発) | `http://localhost:8000/api` |
| ベース URL(本番) | `/api`(Nginx が `/api/` を FastAPI に転送する。画面と同じオリジンなので CORS は不要) |
| データ形式 | JSON(文字コード UTF-8) |
| 項目名 | snake_case(例: `played_on`) |
| 日付 | `YYYY-MM-DD`(例: `2026-11-22`) |
| 点数 | 整数(例: `42500`)。素点・供託は点単位 |
| スコア | 小数(例: `42.5`) |
| 認証 | なし |
| 自動ドキュメント | FastAPI の `/docs`(Swagger UI)で、API を画面から試せる |

開発中は、画面(`localhost:3000`)から API(`localhost:8000`)を呼ぶため、バックエンドで `http://localhost:3000` からのアクセスを許可する(CORS 設定)。

### 1.1 エンドポイント一覧

| No. | メソッド | パス | 説明 | 使う画面 |
|-----|---------|------|------|---------|
| A01 | GET | `/players` | プレイヤー一覧(削除済みを除く) | S03, S04 |
| A02 | POST | `/players` | プレイヤー登録 | S04 |
| A03 | PUT | `/players/{id}` | プレイヤー名の変更 | S04 |
| A04 | DELETE | `/players/{id}` | プレイヤー削除(論理削除) | S04 |
| A05 | GET | `/players/{id}` | プレイヤー詳細(成績と対局履歴) | S05 |
| A06 | GET | `/stats` | 成績一覧(全プレイヤーの成績) | S01 |
| A07 | GET | `/games` | 対局一覧 | S02 |
| A08 | GET | `/games/{id}` | 対局1件の取得 | S03(編集) |
| A09 | POST | `/games` | 対局登録 | S03 |
| A10 | PUT | `/games/{id}` | 対局編集 | S03 |
| A11 | DELETE | `/games/{id}` | 対局削除 | S02 |
| A12 | GET | `/health` | 動作確認(デプロイ後の確認用) | - |

### 1.2 エラー応答

エラーのときは、次の形式で返す。`message` は、そのまま画面に表示できる日本語の文にする。

```json
{
  "message": "入力内容に誤りがあります",
  "errors": [
    { "field": "results", "message": "素点の合計と供託の合計が 120,000点になっていません(現在: 119,000点)" }
  ]
}
```

| ステータス | 意味 | 使う場面 |
|-----------|------|---------|
| 200 | 成功 | 取得、更新 |
| 201 | 作成成功 | 登録 |
| 204 | 成功(返す内容なし) | 削除 |
| 404 | 見つからない | 存在しない ID。削除済みのプレイヤーの更新・削除 |
| 409 | 競合 | プレイヤー名の重複 |
| 422 | 入力が不正 | 入力チェックに失敗した |
| 500 | サーバーエラー | 想定外のエラー |

### 1.3 計算はバックエンドで行う
順位(`rank_from`、`rank_to`)と最終スコア(`final_score`)は、画面から受け取らず、素点からバックエンドが計算して保存する(計算の仕様は[機能要件.md](機能要件.md)の 2.2、2.3 を参照)。対局を登録・編集するときは、同じトランザクションで保存し、途中で失敗したら全部取り消す。

## 2. プレイヤー

### A01 GET `/players`
削除されていないプレイヤーを、登録が古い順に返す。

```json
[
  { "id": 1, "name": "田中" },
  { "id": 2, "name": "佐藤" }
]
```

### A02 POST `/players`
リクエスト:

```json
{ "name": "田中" }
```

レスポンス(201): `{ "id": 1, "name": "田中" }`

| 入力チェック | ステータス | メッセージ |
|-------------|-----------|-----------|
| 名前が未入力(空白だけも含む) | 422 | 名前を入力してください |
| 名前が21文字以上 | 422 | 名前は20文字以内で入力してください |
| 削除されていないプレイヤーと名前が重複 | 409 | その名前はすでに登録されています |

名前は、前後の空白を取り除いてから検査・保存する。

### A03 PUT `/players/{id}`
リクエスト・入力チェックは A02 と同じ(自分自身の現在の名前との重複は、エラーにしない)。レスポンス(200): `{ "id": 1, "name": "田中" }`

存在しない、または削除済みのプレイヤーは 404(「プレイヤーが見つかりません」)。

### A04 DELETE `/players/{id}`
論理削除する(`deleted_at` に現在日時を入れる)。過去の対局は残る。レスポンスは 204。存在しない、または削除済みのプレイヤーは 404。

### A05 GET `/players/{id}`
プレイヤー詳細画面(S05)用。成績と、対局履歴(同卓者つき)を返す。削除済みのプレイヤーでも取得できる(`deleted` が `true` になる)。存在しない ID は 404。

```json
{
  "player": { "id": 1, "name": "田中", "deleted": false },
  "stats": {
    "games_count": 5,
    "total_score": 52.5,
    "max_points": 42500,
    "avg_rank": 2.1,
    "rank_counts": [1.5, 1.83, 1.33, 0.33],
    "top_rate": 0.3,
    "last_rate": 0.0667
  },
  "history": [
    {
      "game_id": 5,
      "played_on": "2026-11-22",
      "points": 29000,
      "rank": 2,
      "final_score": 9.0,
      "table_mates": [
        { "player_id": 2, "name": "佐藤", "deleted": false, "rank": 1, "points": 38000 },
        { "player_id": 4, "name": "高橋", "deleted": false, "rank": 3, "points": 27000 },
        { "player_id": 3, "name": "鈴木", "deleted": false, "rank": 4, "points": 25000 }
      ]
    }
  ]
}
```

| 項目 | 内容 |
|------|------|
| `stats` | 項目と計算は A06 と同じ。対局が0件のときは、`games_count` が 0、ほかは `null`(`rank_counts` は `[0, 0, 0, 0]`) |
| `history` | そのプレイヤーが参加した対局を、対局日の新しい順(同じ日は `game_id` の新しい順)に並べる |
| `rank` | 表示用の順位。(`rank_from` + `rank_to`) ÷ 2(同点なら 1.5 など) |
| `table_mates` | 同卓者3人。順位順に並べる。削除済みのプレイヤーは `deleted` が `true`(画面で「削除されたプレイヤー」と表示する) |

## 3. 成績一覧

### A06 GET `/stats`
成績一覧画面(S01)用。削除されていないプレイヤー全員の成績を返す。並び替えは画面側で行うので、API は並び順を保証しない(`id` の昇順)。

```json
[
  {
    "player_id": 1,
    "name": "田中",
    "games_count": 5,
    "total_score": 52.5,
    "max_points": 42500,
    "avg_rank": 2.1,
    "rank_counts": [1.5, 1.83, 1.33, 0.33],
    "top_rate": 0.3,
    "last_rate": 0.0667
  }
]
```

| 項目 | 内容 | 計算(DB設計書の 6 章を参照) |
|------|------|------|
| `games_count` | 対局数 | 参加した対局の数 |
| `total_score` | 通算スコア | `final_score` の合計 |
| `max_points` | 最高素点 | `points` の最大値 |
| `avg_rank` | 平均順位 | (`rank_from` + `rank_to`) ÷ 2 の平均 |
| `rank_counts` | 1〜4位の回数(4つの数値の配列) | 同点は 1 ÷ 人数 ずつ按分 |
| `top_rate` | トップ率(0〜1) | 1位の回数 ÷ 対局数 |
| `last_rate` | ラス率(0〜1) | 4位の回数 ÷ 対局数 |

対局が0件のプレイヤーは、`games_count` が 0、`total_score`・`max_points`・`avg_rank`・`top_rate`・`last_rate` が `null`、`rank_counts` が `[0, 0, 0, 0]`。画面では「-」と表示する。割合や小数の丸めは、画面側で行う(API は丸めない)。

## 4. 対局

### 対局のデータ(A07〜A10 で共通)

```json
{
  "id": 5,
  "played_on": "2026-11-22",
  "kyotaku": 1000,
  "results": [
    { "player_id": 2, "player_name": "佐藤", "player_deleted": false,
      "points": 38000, "rank_from": 1, "rank_to": 1, "rank": 1, "final_score": 38.0 },
    { "player_id": 1, "player_name": "田中", "player_deleted": false,
      "points": 29000, "rank_from": 2, "rank_to": 2, "rank": 2, "final_score": 9.0 },
    { "player_id": 4, "player_name": "高橋", "player_deleted": false,
      "points": 27000, "rank_from": 3, "rank_to": 3, "rank": 3, "final_score": -13.0 },
    { "player_id": 3, "player_name": "鈴木", "player_deleted": false,
      "points": 25000, "rank_from": 4, "rank_to": 4, "rank": 4, "final_score": -35.0 }
  ]
}
```

- `results` は順位順に並べる(同点は `player_id` の昇順)。
- `rank` は表示用の順位で、(`rank_from` + `rank_to`) ÷ 2。
- 削除済みのプレイヤーは `player_deleted` が `true`。画面で「削除されたプレイヤー」と表示する。

### A07 GET `/games`
全対局を、対局日の新しい順(同じ日は `id` の新しい順)で返す。形は、上の対局のデータの配列。ページ送りはしない(MVP の対象外)。

### A08 GET `/games/{id}`
対局1件を返す。存在しない ID は 404(「対局が見つかりません」)。

### A09 POST `/games`
リクエスト:

```json
{
  "played_on": "2026-11-22",
  "kyotaku": 1000,
  "results": [
    { "player_id": 2, "points": 38000 },
    { "player_id": 1, "points": 29000 },
    { "player_id": 4, "points": 27000 },
    { "player_id": 3, "points": 25000 }
  ]
}
```

レスポンス(201): 上の対局のデータ。`results` の順番は、リクエストでは問わない(バックエンドが順位順に並べ替える)。

### A10 PUT `/games/{id}`
リクエストは A09 と同じ。`results` は丸ごと置き換える。レスポンス(200): 上の対局のデータ。存在しない ID は 404。

### 入力チェック(A09、A10 共通)

画面設計書(S03)のチェックと同じものを、バックエンドでも行う。

| チェック | メッセージ |
|---------|-----------|
| `played_on` がない、または日付として不正 | 対局日を入力してください |
| `results` が4件でない、または `player_id` が足りない | 4人のプレイヤーを選択してください |
| 同じ `player_id` が重複している | 同じプレイヤーを重複して選べません |
| 存在しない `player_id` | 選択したプレイヤーが見つかりません |
| 削除済みのプレイヤーを選んだ(※) | 削除されたプレイヤーは選べません |
| `points` がない | 4人分の素点を入力してください |
| `points` が100の倍数でない | 素点は100点単位で入力してください |
| `kyotaku` が負の数、または100の倍数でない | 供託は0以上の100点単位で入力してください |
| 素点の合計 + 供託 が 120,000 でない | 素点の合計と供託の合計が 120,000点になっていません(現在: ○○点) |

※ 対局の編集(A10)では、その対局にもともと参加している削除済みのプレイヤーは、そのまま選んでよい(新しく削除済みのプレイヤーを加えることだけを禁止する)。

### A11 DELETE `/games/{id}`
対局と、その4人分の結果を削除する(物理削除)。レスポンスは 204。存在しない ID は 404。

## 6. 画面と API の対応

| 画面 | 画面を開いたとき | 操作したとき |
|------|----------------|-------------|
| S01 成績一覧 | A06 | (並び替えは画面側で行う) |
| S02 対局一覧 | A07 | 削除: A11 |
| S03 対局登録 | A01(プレイヤーの選択肢) | 登録: A09 |
| S03 対局編集 | A01、A08 | 更新: A10 |
| S04 プレイヤー管理 | A01 | 登録: A02、名前の変更: A03、削除: A04 |
| S05 プレイヤー詳細 | A05 | - |

S03(編集)では、編集する対局に削除済みのプレイヤーがいる場合、A08 の `results`(`player_deleted` が `true`)から、そのプレイヤーを選択肢に加えて表示する。

## 7. 実装の方針(バックエンド)

| 層 | 役割 | FastAPI での実装 |
|----|------|-----------------|
| ルーター | パスと HTTP メソッドの受け付け、入力の型チェック | `routers/` |
| サービス | 入力チェック、順位・スコアの計算、トランザクション | `services/` |
| モデル | DB のテーブル(SQLAlchemy) | `models/` |
| スキーマ | リクエスト・レスポンスの形(Pydantic) | `schemas/` |

順位とスコアの計算は、サービス層の1つの関数にまとめ、単体テストで、機能要件の計算例(同点の 7 パターンを含む)を確認する。
